# ADR-0016：重复内容检测与处理

- 状态：已接受，延后到扩展阶段
- 日期：2026-07-30

## 背景

资产身份由相对路径决定，因此两个不同路径即使字节内容完全相同，也属于两个资产。仍需决定扫描和应用内导入是否计算内容哈希，以及发现完全重复内容时是否阻止入库。

相似照片、连拍、人脸或视觉相似度不属于本 ADR；这里只讨论字节完全相同的文件。

## 候选方案

### A. 允许重复资产，后台检测并提示（建议）

- 新文件先按路径建立资产并生成基础预览；
- 后台低优先级计算 SHA-256，按哈希和文件大小归组；
- 相同内容的不同路径均保留，不自动删除、合并或迁移标签；
- 提供“重复项”视图，让用户比较路径、组织信息和文件时间后自行决定；
- 应用内导入时若缓存中已有相同哈希，可在移动源文件前提示“资源库中已有相同内容”，由用户选择继续或取消。

优点：不误伤用户有意保留在不同目录的副本；大库扫描不被同步哈希阻塞；规则符合路径身份决策。

代价：重复内容会占磁盘空间；后台哈希大型 RAW 消耗 I/O。

### B. 完全不检测重复内容

只处理文件名冲突，内容相同也不提示。

优点：实现最小，没有额外全文件读取。

代价：资源库容易积累不可见重复副本，也缺少 Billfish/Pixcall 类工具常见的清理能力。

### C. 检测到相同内容时拒绝入库或自动合并

优点：强制节省空间。

代价：与路径即身份冲突；无法表达用户有意把同一文件放在不同文件夹；自动合并组织关系风险高。

## 建议的不变量

- 同名不等于重复，文件名冲突规则保持独立；
- 只有完整内容哈希相同才称为“完全重复”；
- 快速指纹只能筛选候选项，不能直接触发删除；
- 哈希失败不影响资产索引和预览；
- 重复检测不得用于外部改名/移动后的身份匹配。

## 决策

采用 **方案 A：允许重复资产，后台检测并提示**，但该能力属于首期之后的扩展功能。

### 首期边界

- 不实现整库内容哈希后台任务；
- 不实现重复项视图、重复组管理或导入前内容重复提示；
- 只保证同一资源库内相对路径唯一，并执行“同名不覆盖”的文件冲突规则；
- 不自动删除、合并或硬链接任何文件；
- 数据模型可以保留可空内容哈希字段，但不得以此增加首期扫描 I/O。

### 扩展阶段行为

- 后台低优先级计算 SHA-256，按完整哈希和文件大小归组；
- 相同内容的不同路径仍保留为不同资产；
- 提供重复项视图，由用户显式决定保留或删除；
- 哈希失败不影响资产索引、预览或普通操作；
- 重复检测不参与资产身份推断。

## 后果

- 首期大型 RAW 扫描不会因完整文件哈希而增加大量 I/O；
- 首期验收不包含重复内容发现；
- 后续加入重复检测时可增量填充哈希，不需要迁移资产身份规则；
- “重复项”不能在首期菜单或界面中以不可用占位功能出现。
