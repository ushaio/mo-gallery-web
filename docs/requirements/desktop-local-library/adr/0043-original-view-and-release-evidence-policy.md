# ADR-0043：原图查看优先级与未验证能力承诺策略

- 状态：已接受
- 日期：2026-08-02
- 关联：ADR-0028、ADR-0039、ADR-0041

## 决策

下一阶段 P1 的首要体验工作是完善原图查看，而不是优先扩展智能能力或跨模块集成。原图查看必须明确区分屏幕预览、原图模式和系统默认程序打开。

### 原图查看范围

- 默认进入屏幕预览，避免首次打开直接加载超大原文件；
- 用户在预览中点击“原图/100%”后进入原图模式，不让双击直接跳过预览；
- 原图模式按当前查询结果提供上一张/下一张，遵循当前文件夹、搜索、筛选、排序和分页语义；
- 工具栏提供适应窗口、100% 和缩放控制，同时支持滚轮缩放与拖动画布；
- 普通格式按资产 ID 由 Go 侧重新校验并读取库内原文件；
- RAW 只显示最高可用内嵌 JPEG，并明确标注不是 RAW 显影；
- 超大图必须有像素、内存和取消限制；
- 原图读取或解码失败时保留已有屏幕预览，并显示明确原因和重试入口；
- “使用系统默认程序打开”继续作为独立动作。

### 未验证能力

真实媒体样本、硬件、文件系统和干净 Windows 环境缺少证据时，能力标记为“未验证”，不得在 UI、文档或发行说明中宣称完整支持。可以提供安全的建档、占位、组织和重试降级，但必须保留明确提示。

发布采用硬门槛：P0 的真实样本、性能、安全、故障、Windows 和可访问性证据齐全前，不发布包含本阶段新能力的正式版本。开发可并行，但发布承诺不可提前。

## 后果

- 原图查看成为下一阶段最先实施的 P1 功能；
- 媒体能力以证据驱动，不因扩展名白名单自动升级为“完整支持”；
- 验收矩阵必须记录设备、格式样本、资源限制和降级行为；
- 任何新智能或跨模块需求需重新访谈并建立独立 ADR。
