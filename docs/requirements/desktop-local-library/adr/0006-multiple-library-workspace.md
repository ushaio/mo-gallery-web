# ADR-0006：多资源库与工作区模型

- 状态：已接受
- 日期：2026-07-30

## 背景

每个资源库都是包含原文件、索引和组织数据的独立文件夹，并且可以整体迁移。应用需要决定能否登记多个资源库，以及查询和文件操作是否跨库聚合。

## 候选方案

### A. 可登记多个资源库，但一次只打开一个（建议）

应用在自身配置中只保存“最近打开的资源库路径”列表。进入本地资源库时打开一个当前库；切换库会关闭当前数据库、监听器和后台任务，再打开目标库。

优点：每个库边界清晰，查询、标签、集合和文件操作都不会跨库；移动整个库后可以重新定位；资源占用可控。

代价：不能一次搜索所有资源库；切换库需要短暂加载。

### B. 同时打开并聚合多个资源库

应用同时连接多个库，在统一界面中跨库搜索和浏览。

优点：用户可一次查看所有照片。

代价：跨库查询、监听、冲突处理和文件移动复杂；库断开时结果不稳定；弱化独立迁移边界。

### C. 应用只支持一个资源库

首次创建/打开后固定使用该库。

优点：实现最简单。

代价：无法按工作、个人、外接硬盘等场景隔离，未来升级到多库需要迁移全局状态。

## 建议的不变量

- 每个资源库拥有独立 ID，该 ID 存在库内清单中，不由绝对路径决定；
- 最近打开列表只保存定位信息，不承载资产、集合或标签数据；
- 不允许集合、标签关系跨越资源库；
- 从一个资源库向另一个资源库拖放，应视为显式的跨库文件移动/导入命令，不是普通集合操作；首期可不支持。

## 决策

采用 **方案 A：可登记多个资源库，但一次只打开一个**。

- 应用配置保存最近打开的资源库定位列表；
- 同一时间只有一个当前资源库；
- 切换时停止当前库的监听器、扫描器和缩略图任务，关闭数据库，再打开目标库；
- 打开目标库后先校验清单和数据库，再执行一致性扫描并启动监听；
- 查询、集合、标签和普通文件操作都限定在当前库内；
- 首期不提供跨库聚合搜索和跨库拖放。

## 后果

- 后台任务必须携带资源库实例/世代标识，切库后旧任务不得写入新库；
- 最近库路径失效时显示“需要重新定位”，不得自动创建同名空库；
- 从最近列表移除资源库只移除定位记录，不删除资源库文件夹及库内数据；
- 资源库 ID 存在库内清单中，绝对路径变化不会产生新资源库身份。
