# ADR-0008：资源库与线上账号的归属关系

- 状态：已接受
- 日期：2026-07-30

## 背景

本地资源库必须登录后使用，但资源库内容保存在普通磁盘文件夹中。需要明确切换 MO Gallery 线上账号后，是否仍可打开同一本地资源库。

操作系统文件权限才是原文件的实际访问边界。仅在 `library.json` 中记录线上账号并不能阻止同一操作系统用户通过文件资源管理器访问照片，但可以限制应用内的标签和集合数据。

## 候选方案

### A. 资源库不绑定线上账号（建议）

任意有效登录账号都可打开当前操作系统用户有权限访问的资源库。登录只控制是否能进入功能；上传时使用当前登录账号。

优点：资源库可移植，不受服务器地址、账号 ID 变化或账号注销影响；符合本地文件的实际权限模型。

代价：同一操作系统账户下切换 MO Gallery 账号后，仍能看到同一本地库。

### B. 资源库绑定创建它的线上账号

清单记录服务器身份和用户 ID，其他账号登录时拒绝打开。

优点：应用内提供一层账号隔离。

代价：不能保护磁盘原文件；服务器迁移、账号重建或离职交接可能导致库无法打开；需要转移所有权和恢复机制。

### C. 默认绑定，但允许显式共享或转移

优点：兼顾隔离和协作。

代价：需要权限清单、所有权转移和身份恢复，超出本地单用户 MVP。

## 决策

采用 **方案 A：资源库不绑定线上账号**。

- 任意有效登录账号均可打开当前操作系统用户有文件权限访问的资源库；
- `library.json` 不保存用于限制访问的服务器或用户身份；
- 当前登录账号只用于上传、发布等线上动作；
- 更换服务器、重建账号或注销账号不会改变资源库身份和库内数据；
- 从应用退出登录后，受现有认证边界约束，不能继续访问本地资源库页面。

## 后果

- 同一操作系统账户下切换 MO Gallery 账号后，仍可看到同一本地资源库；
- 应用不得用“私有”或“账号加密”等文案误导用户；
- 若未来需要多人隔离，应依赖操作系统账户/目录权限，或另行设计真正的库加密机制；
- 最近资源库列表可以是本机应用级配置，不按线上账号拆分。
