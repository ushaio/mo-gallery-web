# ADR-0018：与现有 Desktop 功能的首期集成

- 状态：已接受
- 日期：2026-07-30

## 背景

Desktop 已有上传队列、线上图库/相册、Zine 编辑器和 AI 助手。本地资源库可以成为这些功能的照片来源，但全部打通会扩大首期范围。现有上传流水线已经接受本地文件路径，因此上传是最低成本且价值明确的集成点。

## 候选方案

### A. 首期只打通现有上传流程（建议）

- 本地资源库支持单选/多选后执行“上传到 MO Gallery”；
- 将原文件路径送入现有上传准备、上传设置和队列；
- 用户仍在现有上传界面配置线上相册、胶卷、分类、存储源、压缩和 GPS 处理；
- 上传成功后本地资产记录可保存可空的线上照片 ID/服务器标识，用于显示“已上传”，但不建立持续双向同步；
- Zine、AI 助手、故事等首期不直接从本地资源库选片。

优点：复用现有 `PrepareUpload`、`UploadFile` 和上传队列，形成“本地整理 → 线上发布”的核心闭环。

代价：其他创作工具首期仍需使用线上照片或各自已有入口。

### B. 首期打通上传 + Zine 本地选片

在 A 基础上允许 Zine 项目引用本地资产预览/原文件。

优点：本地资源库可直接服务创作。

代价：Zine 项目的可移植性、资源库未打开、资产移动/删除、RAW 预览和 PDF 导出都需要定义引用生命周期。

### C. 首期作为全 Desktop 的统一素材选择器

上传、Zine、故事、AI 助手等均可从本地资源库选片。

优点：产品整合最完整。

代价：跨功能合同和异常状态显著扩大，不适合作为资源库基础设施的首个交付阶段。

## 建议的上传边界

- 上传读取原文件，但不得移动、重命名或修改本地资产；
- `preview_unavailable` 的 RAW 仍可尝试上传原文件，是否被服务端接受由现有上传格式能力决定并明确报错；
- 本地标签、集合、评分不默认映射到线上相册或分类；
- 上传状态不是资产身份的一部分，上传失败不影响本地索引；
- 切换服务器后，旧线上照片 ID 不能被误认为当前服务器记录，因此若保存关联需同时保存服务器身份。

## 决策

采用 **方案 A：首期只打通现有上传流程**。

- 本地资源库支持单选/多选资产后执行“上传到 MO Gallery”；
- 复用现有上传准备、设置页面和上传队列，不新建第二套上传实现；
- 上传设置仍由用户选择线上相册、胶卷、分类、存储源、压缩和 GPS 处理；
- 上传过程只读取本地原文件，不移动、重命名或修改资源库资产；
- 上传成功或失败不改变本地资产身份及组织数据；
- 首期不直接接入 Zine、故事编辑器、AI 助手或统一素材选择器；
- 本地标签、集合、评分、颜色和收藏不自动映射线上数据。

### 可选上传关联

本地资产可以保存最近一次成功上传的服务器身份和线上照片 ID，用于显示“已上传”状态；该关联不是双向同步合同。切换服务器时不得把旧服务器照片 ID 当作当前服务器记录。

## 后果

- 可复用现有 `PrepareUpload`、`UploadFile`、上传配置和进度队列；
- 本地资源库页面只负责提交资产路径及必要上下文，上传规则继续由现有模块拥有；
- RAW/HEIC/TIFF 是否可上传取决于服务端上传能力，失败需明确展示，不能因本地可索引就宣称线上也支持；
- 后续 Zine/AI 集成需要单独定义本地引用生命周期。
