# ADR-0015：库外文件拖到集合等逻辑目标

- 状态：已接受
- 日期：2026-07-30

## 背景

文件夹是真实磁盘位置，但集合、标签、收藏和搜索结果只是逻辑视图。用户把库内资产拖到集合时，只需建立集合关系；用户把库外文件直接拖到集合时，还必须先决定原文件在资源库中的真实落盘位置。

## 候选方案

### A. 使用当前真实文件夹作为落盘位置，再添加逻辑关系（建议）

- 如果用户从某个真实文件夹进入集合视图，保留该文件夹作为“当前导入位置”；
- 如果没有可用的当前真实文件夹，则落到资源库根目录；
- 拖到集合：移动文件并创建资产，然后加入该集合；
- 拖到标签：移动文件并创建资产，然后添加该标签；
- 拖到收藏：移动文件并创建资产，然后标记收藏；
- 搜索结果本身不接受外部拖放，因为搜索条件可能无法转换为确定的写操作。

优点：拖放一步完成，且遵循已确定的“根目录/当前目录”规则。

代价：用户可能只注意到集合名，忽略文件实际落盘目录；需要在拖放提示中同时显示物理目标和逻辑动作。

### B. 逻辑目标不接受库外文件拖放

只有资源库根目录和真实文件夹接受库外文件。用户先完成导入，再将库内资产拖入集合、标签或收藏。

优点：物理移动与逻辑组织完全分离，没有隐式落盘位置。

代价：多一步操作，集合导入体验不如成熟资源管理工具直接。

### C. 拖到逻辑目标时先弹出真实文件夹选择器

用户选择落盘文件夹后，应用再移动文件并添加逻辑关系。

优点：落盘位置明确，仍可一步建立逻辑关系。

代价：每次拖放增加弹窗，批量整理体验较重。

## 决策

采用 **方案 B：逻辑目标不接受库外文件拖放**。

- 库外文件只能拖入资源库根目录、当前真实文件夹内容区或真实文件夹节点；
- 集合、标签、收藏和搜索结果拒绝库外文件拖放，不隐式决定磁盘落盘位置；
- 文件成为库内资产后，才允许拖到集合、标签或收藏以修改逻辑关系；
- 搜索结果不作为可写拖放目标；
- 拒绝外部拖放时应使用不可放置光标/状态，不在放下后才弹出含糊错误。

## 后果

- 物理文件移动与逻辑组织保持严格分离；
- 用户从库外文件到集合至少需要“导入到文件夹 → 添加到集合”两步；
- 拖放数据载荷必须区分操作系统外部文件与当前库内资产 ID；
- 库内资产拖到文件夹执行磁盘移动，拖到集合/标签/收藏只修改数据库关系。
