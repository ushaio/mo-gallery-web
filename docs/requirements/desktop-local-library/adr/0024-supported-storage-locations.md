# ADR-0024：资源库支持的存储位置

- 状态：已接受
- 日期：2026-07-30

## 背景

资源库在同一目录树中保存原文件、SQLite 数据库、缩略图、回收站和写锁。不同存储位置对原子改名、文件锁、监听事件、掉线恢复和数据库一致性的保证不同。

## 候选方案

### A. 首期正式支持本机磁盘与直连外接盘（建议）

正式支持：

- 本机固定磁盘上的普通用户目录；
- USB/Thunderbolt 直连 HDD、SSD 等外接卷；
- Windows NTFS/exFAT（具体格式按测试结果列出），后续 macOS 阶段验证 APFS/exFAT。

首期不正式支持：

- SMB/NFS/NAS 网络共享；
- OneDrive、Dropbox、iCloud Drive 等同步中的云盘目录；
- WebDAV、虚拟文件系统和按需下载占位文件；
- 多台电脑同时打开同一资源库。

优点：文件锁、SQLite WAL、原子文件操作和监听语义更可控，符合“本地资源库”的首期定位。

代价：NAS 用户不能获得正式兼容承诺；云盘目录即使能创建也应警告或拒绝。

### B. 同时正式支持 NAS/SMB

优点：大型照片库常存放在 NAS，可直接管理。

代价：网络断开、锁实现、监听可靠性、延迟和 SQLite WAL 兼容都需专项设计；不能把映射盘当作普通本地盘测试。

### C. 同时正式支持云同步目录

优点：资源库可经现有云盘跨设备同步。

代价：SQLite/WAL、缩略图和回收站会频繁同步，冲突副本可能损坏索引；按需文件不一定真正存在本地；需要专门的同步安全协议。

## 建议的不变量

- 创建/打开前识别卷类型和可写能力；
- 卷意外断开时暂停所有写入、监听和预览任务，不能把全库资产批量标记失联；
- 卷恢复后通过库 ID 确认同一资源库，再执行校准；
- 可用磁盘空间不足时停止导入/预览任务并保留可恢复状态；
- 不因路径仍存在就假定数据库锁和原子改名语义可靠。

## 决策

采用 **方案 A：首期正式支持本机磁盘与直连外接盘**。

### 正式支持

- Windows 10/11 本机固定 HDD/SSD；
- USB/Thunderbolt 等直连外接 HDD/SSD；
- Windows 上经过实际测试的 NTFS 与 exFAT；
- 后续 macOS 阶段再验证 APFS 与 exFAT。

### 首期不正式支持

- SMB、NFS、NAS 网络共享和映射网络盘；
- OneDrive、Dropbox、iCloud Drive 等同步目录；
- WebDAV、虚拟文件系统、按需下载占位文件；
- 多台电脑同时打开同一资源库。

### 卷断开行为

- 资源库卷意外断开时暂停数据库写入、监听、导入和预览任务；
- 不因整个卷不可访问而将全库资产批量标记为 `missing`；
- 卷恢复后读取资源库清单并校验库 ID，确认同一资源库后再恢复任务和校准；
- 磁盘空间不足时停止产生新文件的任务，并保留可恢复的任务状态。

## 后果

- 创建和打开资源库前需要检测卷类型、可写性和可用空间；
- 对不受支持位置应拒绝或明确标记为实验性，不能静默当作已兼容；
- SQLite 模式和文件锁策略只对声明支持的文件系统作保证；
- 后续 NAS/云同步需要单独 ADR 和一致性设计。
