# ADR-0022：搜索、筛选与排序范围

- 状态：已接受
- 日期：2026-07-30

## 背景

单库目标为 100,000 项资产，仅依赖文件夹树无法满足查找需求。但 OCR、视觉相似搜索、自然语言和复杂布尔语法会引入新的索引与 AI 能力，不应仅因参考 Billfish/Pixcall 自动进入首期。

## 候选方案

### A. 统一关键词搜索 + 结构化筛选（建议）

关键词搜索覆盖：

- 文件名与相对路径；
- 显示标题和备注；
- 标签名、集合名；
- 相机厂商/型号和镜头名称。

结构化筛选覆盖：

- 真实文件夹、集合、标签；
- 收藏、评分区间、颜色标记；
- 文件格式、预览状态、失联/回收状态；
- 拍摄日期范围、导入/发现日期范围；
- 相机、镜头、ISO、光圈、焦距等可用 EXIF 条件；
- 横向/纵向/方形及宽高范围。

排序覆盖：

- 拍摄时间、文件修改时间、发现时间；
- 文件名、文件大小、评分；
- 升序/降序。

关键词与筛选条件组合为 AND；同一筛选组中的多选默认 OR。首期不要求用户编写查询语法。

优点：覆盖常见摄影资产检索，规则可解释，可由 SQLite 索引与 FTS 实现。

代价：筛选器数量较多，需要可折叠面板和清晰的已应用条件摘要。

### B. 精简搜索

只搜索文件名、标题和标签，只筛选文件夹、集合、收藏、评分、颜色及格式。

优点：实现和界面更小。

代价：无法按拍摄日期、器材和曝光参数快速定位照片，10 万项库的检索价值有限。

### C. 在 A 基础上加入 OCR、以图搜图和自然语言

优点：接近高级素材管理工具。

代价：需要本地模型、向量索引、隐私与资源调度设计；应作为独立扩展阶段。

## 建议的非目标

- 首期不做 OCR、人物/人脸识别、物体自动标签；
- 首期不做感知哈希相似图或向量搜索；
- 首期不提供正则表达式、SQL 或复杂查询语言；
- 搜索只在当前资源库内执行。

## 决策

采用 **方案 A：统一关键词搜索 + 结构化筛选**。

### 关键词范围

- 文件名与相对路径；
- 显示标题与备注；
- 标签名与集合名；
- 相机厂商/型号与镜头名称。

### 筛选范围

- 文件夹、集合、标签；
- 收藏、评分区间、颜色标记；
- 格式、预览状态、失联状态和回收状态；
- 拍摄日期与发现日期；
- 相机、镜头、ISO、光圈、焦距；
- 横向、纵向、方形及可用尺寸条件。

### 排序范围

- 拍摄时间、文件修改时间、发现时间；
- 文件名、文件大小、评分；
- 升序与降序。

### 组合语义

- 关键词与不同筛选组之间使用 AND；
- 同一筛选组中的多选默认使用 OR；
- 活跃条件以可移除条件项显示，可一键清除；
- 首期不暴露查询语言、正则表达式或 SQL。

## 实现边界

- 搜索和筛选只在当前资源库内执行；
- 使用 SQLite 索引/FTS 与分页查询，不将全库记录发送到 React；
- OCR、自然语言、人脸/物体识别、感知哈希和向量相似搜索延后；
- EXIF 缺失时该资产不匹配对应结构化条件，但仍可通过其他字段检索。
