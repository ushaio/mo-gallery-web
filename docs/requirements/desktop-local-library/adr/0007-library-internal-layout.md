# ADR-0007：资源库内部布局与缓存位置

- 状态：已接受
- 日期：2026-07-30

## 背景

索引、集合、标签等数据必须随资源库迁移。缩略图和预览图可以重新生成，但体积可能很大。需要决定它们与不可重建用户数据的存放位置。

## 建议的基础布局

```text
<资源库根目录>/
├─ 用户照片与自建文件夹/
└─ .mo-gallery/
   ├─ library.json
   ├─ library.db
   └─ ...
```

- `.mo-gallery/library.json`：库 ID、格式版本、创建时间等最小清单；
- `.mo-gallery/library.db`：资产索引、集合、标签、评分等库内数据；
- `.mo-gallery` 是应用保留目录，扫描器必须排除，用户不应在应用内重命名或删除；
- 数据库保存标准化相对路径，不保存资源库根目录的绝对路径；
- SQLite WAL/临时文件在正常关库时检查点并清理，保证整个文件夹可迁移。

## 候选方案

### A. 数据与缩略图全部随库保存（建议）

```text
.mo-gallery/
├─ library.json
├─ library.db
└─ thumbnails/
```

优点：整个文件夹复制到新位置或新电脑后，首次打开即可快速浏览；所有库相关数据集中；外接硬盘自包含。

代价：资源库体积更大；同步/备份工具会携带大量可再生成缓存；不同操作系统需处理隐藏目录规则。

### B. 用户数据随库，缩略图放应用全局缓存

库内只保存清单和数据库；缩略图按库 ID 存在系统应用数据目录。

优点：资源库更干净、更适合备份；缓存可由应用统一清理。

代价：迁移到新电脑后必须重建全部缩略图；外接盘首次在另一台机器打开较慢；缓存生命周期与库路径重定位更复杂。

### C. 库内保存可选缩略图缓存

默认按 A 或 B，设置中允许切换。

优点：兼顾便携与空间占用。

代价：首期增加迁移、切换与双位置清理逻辑，不建议作为 MVP。

## 决策

采用 **方案 A：数据与缩略图全部随库保存**。

```text
<资源库根目录>/
├─ 用户照片与自建文件夹/
└─ .mo-gallery/
   ├─ library.json
   ├─ library.db
   └─ thumbnails/
```

- 清单、数据库和缩略图均位于资源库保留目录 `.mo-gallery`；
- 复制或移动整个资源库文件夹即可迁移完整资源库；
- 在新位置打开时通过库内清单识别同一资源库，不依赖旧绝对路径；
- 缩略图可删除并重建，数据库和清单不可当作缓存清理；
- 扫描、统计和文件夹树均排除 `.mo-gallery`。

## 后果

- 外接硬盘上的资源库在另一台设备打开时可直接复用缩略图；
- 备份工具默认会携带缩略图，文档需说明 `thumbnails` 可选择性排除；
- 需要检测 `.mo-gallery` 缺失、数据库损坏、版本不兼容和只读资源库；
- `.mo-gallery` 内的数据库、WAL 和缓存文件不得触发资产监听事件。
