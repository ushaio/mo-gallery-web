# ADR-0002：原文件所有权与导入策略

- 状态：已接受
- 日期：2026-07-30

## 背景

“导入本地照片”可能只是在数据库登记现有文件，也可能由应用复制文件到自己的资源目录。二者在磁盘占用、文件失联、备份和删除风险上完全不同，必须在数据模型和扫描器实现之前确定。

## 决策驱动因素

- 是否允许应用重新组织用户文件；
- 是否接受同一照片额外占用一份磁盘空间；
- 外接硬盘离线、用户在资源管理器中移动文件时的行为；
- 资源库是否需要可整体迁移和备份；
- 资源库内正常文件的删除与失联索引清理必须有清晰、安全的不同语义。

## 候选方案

### A. 引用原文件（建议作为 MVP）

用户添加来源文件夹后，应用仅保存文件路径/标识和元数据，原文件原地不动；缩略图进入应用缓存。

优点：导入快、不重复占用原图空间、符合“管理已有照片”的需求。

代价：用户在资源管理器中移动/删除文件后会产生失联资产，需要重连和重新扫描机制。

### B. 托管副本

导入时将原文件复制到应用管理的目录，资源库管理该副本。

优点：路径稳定，便于整体备份和迁移。

代价：占用额外空间，容易让用户误解哪一份是主文件；需处理副本命名、目录结构与磁盘容量。

### C. 同时支持引用和托管

每次添加来源时让用户选择，数据模型记录资产所有权模式。

优点：灵活，接近成熟 DAM 产品。

代价：首期复杂度显著上升，移动、删除、去重、导出和备份都必须处理两套语义。

## 决策

采用受资源库边界约束的**引用原文件**方案：

- 不允许资源库长期引用任意散落在库外的绝对路径；
- 一个磁盘文件夹构成一个独立资源库；
- 本地资产的原文件必须位于该资源库根目录或其子目录中；
- 资产记录优先保存相对资源库根目录的路径；
- 索引及需要随库迁移的组织信息存放在对应资源库内；
- 移动整个资源库目录后，应可在新位置重新打开，不需要逐张重连。

该方案不是“托管副本”：应用不必把所有原文件集中到全局应用目录，也不拥有库外原文件。外部文件加入库时究竟复制、移动还是拒绝，留给 ADR-0003 决定。

## 不变量（无论选择何种方案）

- 缩略图只是缓存，可以删除并重新生成。
- 资源库不得静默引用库根目录之外的文件。
- 持久化资产路径应相对于资源库根目录，避免迁移后绝对路径失效。
- 正常可用资产不提供“只移除索引、文件仍留在库内”的动作；只要文件仍位于库内，就属于扫描和管理范围。
- 删除正常资产会处理库内文件，默认移入资源库回收站；批量永久删除不得静默执行。
- 仅当文件已不在记录路径、资产处于 `missing` 时，才允许“移除失联记录”以清理索引和组织数据。
