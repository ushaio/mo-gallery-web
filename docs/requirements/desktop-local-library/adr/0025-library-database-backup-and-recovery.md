# ADR-0025：资源库数据库备份与恢复

- 状态：已接受
- 日期：2026-07-30

## 背景

原文件、基础 EXIF 和路径索引可以重新扫描，但集合、标签、评分、颜色、收藏、显示标题、备注以及回收状态只存在于 `.mo-gallery/library.db`。数据库损坏或升级失败时，仅重建索引会永久丢失用户整理成果。

## 候选方案

### A. 库内自动滚动备份 + 手动备份（建议）

- 每次数据库 schema 升级前创建一致性备份；
- 每日首次成功打开并发生数据变更后创建一次备份；
- 默认保留最近 7 个日备份和 3 个升级前备份；
- 备份存放于 `.mo-gallery/backups/`，随资源库迁移；
- 设置中提供“立即备份”和“从备份恢复”；
- 恢复前先备份当前数据库，即使当前库疑似损坏也尽量保留诊断副本；
- 缩略图不进入数据库备份，可按需重建。

优点：保护不可重建的整理数据；资源库仍然自包含；schema 升级失败可回退。

代价：备份会额外占用空间；需要一致性快照、保留策略和恢复 UI。

### B. 只在 schema 升级前自动备份

优点：空间和实现成本较低，能覆盖升级风险。

代价：不能覆盖普通运行中的磁盘损坏、误操作或数据库文件被外部工具破坏。

### C. 不自动备份，只提供导出/手动复制说明

优点：实现最小。

代价：用户通常不会及时备份；与大量不可重建组织数据的风险不匹配。

## 建议的不变量

- 不能在 SQLite 正在写入时直接复制 `library.db` 文件，必须使用一致性备份 API/检查点策略；
- 自动备份失败不得阻止只读浏览，但 schema 升级前备份失败应阻止升级写入；
- 恢复操作必须要求独占库锁并停止监听和后台任务；
- 备份不包含原照片，不能宣传为完整照片备份；
- 用户永久删除的原文件不会因数据库恢复而重新出现。

## 决策

采用 **方案 A：库内自动滚动备份 + 手动备份**。

### 自动备份

- 每次数据库 schema 升级前创建一致性备份；
- 每日首次成功打开且发生数据变更后创建日备份；
- 默认保留最近 7 个日备份和 3 个升级前备份；
- 备份存放于 `.mo-gallery/backups/`，随资源库迁移；
- 使用 SQLite 一致性备份 API 或经过验证的检查点流程，不在写入期间直接复制数据库文件。

### 手动与恢复

- 提供“立即备份”，显示最近备份时间、类型和大小；
- 提供“从备份恢复”，恢复前停止监听、扫描和预览任务并持有独占库锁；
- 恢复前尽量保存当前数据库诊断副本；
- schema 升级前备份失败时阻止升级；普通日备份失败不阻止只读浏览，但需明确提示。

### 边界

- 备份不包含原照片，也不包含可重建缩略图；
- 数据库恢复不会恢复已经永久删除的原文件；
- 不把该能力称为“完整资源库备份”或“照片备份”。

## 后果

- `.mo-gallery/backups` 需要保留策略、空间统计和损坏校验；
- 数据库 schema 迁移必须与备份/恢复流程协同；
- 自动备份属于后台低优先级任务，但不能与关库或卷断开竞态；
- 用户仍需使用外部备份方案保护照片原文件和整个资源库目录。
