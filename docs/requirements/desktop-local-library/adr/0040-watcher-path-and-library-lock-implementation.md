# ADR-0040：Watcher、真实路径与资源库锁实现选型

- 状态：已接受（Windows/真实介质验证仍待完成）
- 日期：2026-07-31
- 关联：ADR-0023、ADR-0024、ADR-0034、ADR-0037

## 背景

资源库允许用户在系统文件管理器中修改普通目录树，因此需要运行期监听与周期性全量校准。同时必须防止路径逃逸、两个写入者并发修改同一资源库，以及外接卷断开时把整库误判为失联。

## 决策

采用四层组合，而不是把任一单点机制当作完整一致性保证：

1. Wails 全局单实例；
2. 资源库级独占写保护；
3. `fsnotify` 递归目录监听与去抖；
4. 打开/恢复时的全量校准作为最终一致性来源。

## 全局单实例

使用 Wails v2.12 `options.SingleInstanceLock`。第二次启动不创建第二个可操作窗口，而是显示并取消最小化已有窗口。该约束覆盖整个 Desktop，不只覆盖本地资源库页面。

## 资源库级写保护

打开资源库前在 `.mo-gallery/lock` 使用 `O_CREATE|O_EXCL` 创建诊断锁记录，当前记录包含 PID 与创建时间；关闭资源库时删除。存在锁时默认拒绝打开，不提供只读模式。

当前实现通过 PID 存活判断回收本机陈旧锁。这不是跨机器可靠的 OS 文件锁，也不能单独证明网络共享上的互斥：

- PID 可能复用；
- 远端机器 PID 无法由本机可靠判断；
- 网络文件系统的 `O_EXCL`、缓存和原子语义不在当前承诺范围。

因此正式支持范围仍限于经过验证的本机固定盘和直连外接盘；NAS、SMB/NFS、云同步目录和多机同时打开不受支持。发布前必须验证 PID 复用防护、异常退出陈旧锁和两个真实进程竞争。若验证不满足要求，应升级为 Windows 持久文件句柄锁，并保留诊断记录。

## 路径策略

- API 只接受资源库相对路径或不透明资产 ID；
- 拒绝绝对路径、`..`、NUL、Windows 保留名称、尾随点/空格和 `.mo-gallery`；
- Windows `path_key` 采用大小写不敏感形式；
- 每次 I/O 将目标拼接后再次检查仍位于同卷和库根之下；
- 对已存在路径执行 `filepath.EvalSymlinks`，解析后逃出库根即拒绝；
- 扫描和 watcher 跳过符号链接目录与 `.mo-gallery`。

当前 `EvalSymlinks` 只覆盖调用时已经存在的目标；不存在目标的父链、junction/reparse point 与检查后替换仍需要 Windows 专项 TOCTOU 测试。未通过验证前不能声称所有链接逃逸均已被完全封堵。

## Watcher 选择与事件模型

使用 `github.com/fsnotify/fsnotify`：

- 打开资源库时递归枚举普通目录并逐目录注册；
- 新增、删除或改名目录时重新建立监听集合或回退全量扫描；
- 忽略 `.mo-gallery` 和应用自身已登记的短期 watcher 路径；
- Create/Write/Remove/Rename 事件以 700 ms 去抖并按相对路径合并；
- 普通文件事件进入与扫描、导入共用的 reconciliation 管线；
- watcher 错误、未知目录变化或无法安全归类的事件回退全量扫描；
- watcher 事件可以丢失、重复、乱序，不能作为唯一事实来源。

## 卷断开与恢复

数据库或 watcher 操作表明资源库不可用时：

- 取消扫描和写入任务；
- 关闭 watcher；
- session 进入 `suspended`，不执行全库 missing 标记；
- 周期性探测路径、清单和 Library ID；
- 同一资源库恢复后重建 watcher 并启动全量校准；
- 路径重新出现但 Library ID 不符时进入 `repair_required`，不继续写入。

## 已验证与未验证边界

自动测试已经覆盖部分生命周期、校准、写锁和 suspended/recovery 行为，但以下发布证据仍缺失：

- Windows 两个真实进程竞争；
- 大批复制、临时改名、同路径覆盖和 watcher 事件风暴；
- watcher 丢事件后全量校准修复；
- NTFS 大小写、长路径、junction/reparse point 与链接 TOCTOU；
- exFAT 外接卷强制断开和同盘重新挂载；
- 干净 Windows 10/11 VM 的单实例聚焦行为。

## 后果

- `fsnotify` 提供低延迟发现，全量校准提供最终一致性；
- 路径边界必须在每次真实 I/O 前校验，不能只依赖数据库中的旧路径；
- 资源库锁和 Wails 单实例解决不同层次的问题，二者都必须保留；
- 未完成真实介质和 Windows 验证前，ADR-0023/0024 不能视为发布验收完成。
