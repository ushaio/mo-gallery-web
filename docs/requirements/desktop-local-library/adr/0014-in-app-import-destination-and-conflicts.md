# ADR-0014：应用内导入目标与文件冲突

- 状态：已接受
- 日期：2026-07-30

## 背景

应用内导入会把库外文件移动进当前资源库。必须明确目标真实文件夹；否则拖入主网格时无法决定文件落盘位置。还需避免重名覆盖以及批量任务半成功后难以理解。

## 候选方案

### A. 导入到当前选中的真实文件夹，无选中时进入固定“收件箱”（建议）

- 在真实文件夹视图中导入时，目标是当前文件夹；
- 直接拖到某个文件夹节点时，目标是该节点；
- 在“全部资产”、集合、标签或搜索结果中导入时，目标为库根下的应用默认文件夹（例如 `Inbox/`，显示名可本地化）；
- 导入确认中始终显示目标相对路径，并允许改选真实文件夹。

优点：上下文行为自然，又为逻辑视图提供确定落点；不会把照片散落在库根。

代价：应用会创建一个真实的默认文件夹，需要定义用户重命名/删除后的行为。

### B. 每次导入都必须选择目标文件夹

优点：没有隐式落点，用户完全控制目录结构。

代价：频繁导入步骤多，拖放不能立即执行。

### C. 所有文件统一进入固定“收件箱”

优点：规则最简单，适合先导入后整理。

代价：即使用户正在浏览明确文件夹，也不能直接导入到当前位置，整理成本更高。

## 建议的冲突规则

- 永不覆盖已有文件；
- 目标存在同名文件时，按 ADR-0036 显示冲突处理，可自动生成不冲突名称（例如 `IMG_001 (1).CR3`）或跳过；
- 自动重命名不是无条件全局默认；用户可逐项处理或将策略应用到当前批次，首期不提供“覆盖”；
- 内容哈希去重与文件名冲突是两个概念：同名不一定重复，不同名也可能内容相同；
- 批量导入逐文件记录结果，失败项不影响已成功项，提供可读结果摘要；
- 跨卷移动采用“复制到临时文件 → 完整性校验 → 原子改名 → 删除源文件”，删除源文件失败时不得谎报为移动成功。

## 决策

不创建固定“收件箱”。应用内导入的真实目标目录由拖放位置和当前浏览路径决定：

- 用户位于资源库顶层且没有进入子文件夹时，拖入文件移动到资源库根目录；
- 用户正在浏览某个真实文件夹时，拖入文件移动到该当前文件夹；
- 用户直接拖到文件夹树中的某个文件夹节点时，移动到该目标文件夹；
- 文件移动成功后立即在目标相对路径创建资产索引；
- 资源库根目录允许直接存放照片，不强制应用创建额外收件箱目录。

示例：

```text
当前浏览位置                     导入结果
资源库顶层                       <库根>/IMG_001.CR3
2025                             <库根>/2025/IMG_001.CR3
拖到 2026/青岛 文件夹节点        <库根>/2026/青岛/IMG_001.CR3
```

集合、标签、收藏和搜索结果不是磁盘路径。库外文件直接拖到这些逻辑目标时的落盘与关系创建规则，由 ADR-0015 决定。

## 文件冲突决策

- 永不覆盖已有文件；
- 目标存在同名文件时，默认生成不冲突名称，例如 `IMG_001 (1).CR3`；
- 可选择跳过同名文件，首期不提供覆盖；
- 批量导入逐文件记录结果，部分失败不回滚已成功项；
- 跨卷移动使用“复制到临时文件 → 完整性校验 → 原子改名 → 删除源文件”。

## 后果

- 拖放命中测试必须明确区分文件夹节点、当前文件夹内容区和逻辑组织目标；
- 界面需持续显示当前真实相对路径，避免用户不知道原文件将移到何处；
- 资源库根目录与任意子文件夹具有一致的资产容器语义。
