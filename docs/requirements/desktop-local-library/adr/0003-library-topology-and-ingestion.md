# ADR-0003：资源库拓扑与外部文件入库方式

- 状态：已接受
- 日期：2026-07-30

## 背景

已决定一个文件夹构成一个资源库，资产只能引用该目录树内的原文件。仍需定义用户从资源库外拖入照片时的行为，否则无法落实路径边界。

## 已确定的不变量

- 一个本地资产只属于一个资源库；
- 资产原文件必须位于资源库根目录之下；
- 库内资产以相对路径定位；
- 不保存指向库外文件的长期引用；
- 移动资源库根目录后可以重新打开。

## 候选方案

### A. 默认复制到资源库（建议）

从库外拖入/选择文件时，复制到资源库内指定目录，再为库内副本建立索引。外部原件保持不动。

优点：不会意外破坏用户原目录，符合“导入”的安全预期，资源库可完整迁移。

代价：产生一份副本；需要目标目录、重名和重复内容处理规则。

### B. 默认移动到资源库

将外部文件移动到资源库内后索引。

优点：不重复占用空间，最终只有库内一份文件。

代价：属于破坏性文件操作，可能打乱用户原目录或其他软件引用；不适合作为无提示默认行为。

### C. 不提供外部导入，只扫描用户已放入库内的文件

应用只索引资源库内已有文件。用户必须通过系统文件管理器自行复制/移动照片。

优点：应用完全不修改用户文件，首期最简单。

代价：体验割裂，拖拽导入和批量整理能力弱。

### D. 每次让用户选择复制或移动

提供两种显式操作，但默认仍需确定。

优点：灵活。

代价：交互和冲突处理范围更大；用户可能误选移动。

## 决策

区分应用内操作与系统文件资源管理器操作，两条入口遵循不同命令语义：

### 应用内导入

应用内导入不再静默决定“复制”还是“移动”：

- 用户第一次通过应用拖放或选择库外照片时，必须明确选择“复制到资源库”或“移动到资源库”；
- 首次选择确认后，保存为应用级的“本地资源库导入方式”偏好；
- 后续应用内导入直接使用该偏好，不再每次弹出选择；
- 用户可在“系统设置 → 本地资源库”中修改该偏好；
- 首次选择被取消时，不执行导入，也不写入默认值；
- 该偏好只控制应用内导入，不影响用户通过系统文件资源管理器自行复制、移动或整理文件；
- 无论选择复制还是移动，文件安全落盘后都要立即建立资产索引，不依赖文件监听器再次发现；
- 复制模式下，库内副本成为本地资源库管理的原文件，库外源文件保持不动；
- 移动模式下，源文件在安全移动完成后成为本地资源库管理的原文件，不保留移动前位置的长期引用。

复制或移动的目标子目录、重名冲突、中途失败恢复和跨卷语义遵循文件操作与冲突 ADR；两种模式都不得覆盖目标文件。

### 系统文件资源管理器操作

- 用户可像操作普通文件夹一样，在应用外复制、移动、重命名或删除资源库内文件；
- 应用运行时监听资源库目录树并增量更新索引；
- 应用启动或重新打开资源库时执行一致性扫描，将关闭期间发生的变化纳入索引；
- 文件监听是低延迟提示，一致性扫描才是修复遗漏事件的最终依据。

## 后果

- 应用内“导入”按已保存偏好执行复制或移动；首次选择与设置页必须明确两者是否保留源文件；
- 扫描器必须排除资源库自身的索引与缓存目录，避免把派生文件识别为照片；
- 应用内操作和文件监听事件可能同时到达，需要幂等处理，不能重复创建资产；
- 外部重命名/移动是否保留既有资产身份及标签，由 ADR-0004 决定。
