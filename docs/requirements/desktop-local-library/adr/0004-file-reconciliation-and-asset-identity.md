# ADR-0004：文件系统校准与资产身份

- 状态：已接受
- 日期：2026-07-30

## 背景

用户可以在系统文件资源管理器中修改资源库。仅以相对路径作为资产身份时，重命名或移动会表现为“旧资产删除 + 新资产加入”，从而丢失标签、评分、集合关系和其他用户整理数据。

## 已确定的同步机制

1. 应用启动或打开资源库时执行全库一致性扫描；
2. 应用运行期间监听文件系统事件并触发增量校准；
3. 监听事件可以丢失、合并、乱序或重复，因此处理必须幂等；
4. 应用内文件命令主动更新索引，监听器只负责验证和补漏；
5. 新发现的受支持文件自动纳入索引，不要求用户再次导入。

## 待决定：外部移动后的身份

### A. 能可靠匹配时保留资产身份（建议）

扫描器结合平台文件标识、文件大小、时间和内容哈希判断重命名/移动。只有匹配唯一且可信时更新相对路径，并保留资产 ID、标签、评分和集合关系；无法唯一判断时不自动合并，进入待处理状态。

优点：符合用户“只是整理文件夹”的预期，最大程度保留整理成果。

代价：需要文件指纹和歧义处理；完全相同的重复文件不能只靠哈希区分。

### B. 路径就是身份

原路径消失时将旧资产标记失联；新路径始终创建新资产。

优点：实现简单且规则确定。

代价：在资源管理器中改名或移动就会丢失原资产上的整理关系，不符合资源管理软件的常见预期。

## 建议的校准状态

- `indexed`：索引与原文件一致；
- `pending`：新文件等待提取元数据/生成缩略图；
- `missing`：索引存在但原路径不可访问；
- `ambiguous`：发现可能的移动或重复项，但无法唯一匹配；
- `unsupported`：文件存在但格式不受支持，不创建资产。

## 决策

采用 **方案 B：路径就是身份**。

- 资产身份绑定资源库内的相对路径；
- 用户通过系统文件资源管理器移动或重命名文件时，旧路径对应的资产转为 `missing`，保留原有标签、评分和集合关系，供用户识别或处理；
- 新路径按新资产纳入索引，不自动继承旧资产的组织数据；
- 不通过内容哈希自动推断两个路径是同一资产；
- 产品应引导用户尽量在 MO Gallery Desktop 内执行移动、重命名、删除等会改变路径的操作；
- 应用内路径变更作为领域命令执行，在文件操作成功后原子更新原资产路径，因此可以保留资产 ID 和组织数据。

## 后果

- 文件系统校准逻辑更确定，不需要启发式移动匹配和歧义合并；
- 外部改名或移动会产生一个失联旧资产和一个新资产，这是明确接受的行为；
- 需要提供失联资产视图，以及移除失联记录的操作；
- 界面必须区分“应用内移动”和“在资源管理器中移动”的结果；
- 内容哈希仍可用于查找重复内容，但不参与资产身份迁移。
