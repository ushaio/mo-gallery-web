# ADR-0026：集合与标签的层级规则

- 状态：已接受
- 日期：2026-07-30

## 背景

真实文件夹天然形成磁盘目录树。集合和标签是数据库中的逻辑组织结构，是否允许层级会影响左侧导航、拖放、重命名、删除和筛选语义。

## 候选方案

### A. 集合允许分组层级，标签保持扁平（建议）

- 集合可放入“集合组”，例如 `客户/婚礼精选`、`个人/年度最佳`；
- 集合组只包含子组或集合，不直接包含资产；
- 资产加入最末端集合；
- 标签保持扁平，通过搜索和排序管理，不把斜杠等字符解释为层级；
- 文件夹层级、集合组层级和标签列表在左栏分区显示。

优点：集合数量增长后仍可整理，同时避免标签父子继承、同名路径和筛选语义复杂化。

代价：需要额外的集合组模型和拖放排序；标签很多时主要依赖搜索。

### B. 集合和标签都保持扁平

优点：实现与交互最简单，重命名和删除没有树结构级联。

代价：大量集合或标签时左栏难以管理，不接近成熟资产管理工具体验。

### C. 集合和标签都允许任意层级

优点：组织能力最强。

代价：必须决定选中父标签是否包含所有子标签、资产打父标签还是叶子标签、移动节点后的查询含义和循环约束；首期复杂度较高。

## 建议的不变量

- 集合组不能直接包含资产；
- 删除非空集合组需要明确是连同子项删除还是提升子项，不能静默级联；
- 删除集合只删除逻辑关系，不删除原文件；
- 删除标签只移除标签关系，不删除资产；
- 集合组和集合可以排序，标签默认按名称/使用频率排序；
- 首期不实现按查询条件自动更新的“智能集合”，可作为扩展能力。

## 决策

采用 **方案 A：集合允许分组层级，标签保持扁平**。

- 集合可归入集合组，集合组可嵌套；
- 集合组只包含子组或集合，不直接包含资产；
- 资产与实际集合建立多对多关系；
- 标签保持扁平，不将 `/`、`.` 等名称字符解释为父子层级；
- 标签通过搜索、名称排序和使用频率管理；
- 文件夹树、集合树和标签列表在库内左栏分区展示。

### 删除与移动

- 删除集合只删除集合及其资产关系，不删除原文件；
- 删除标签只删除标签及其资产关系；
- 删除非空集合组必须明确选择“连同子集合删除”或取消，首期不隐式提升子节点；
- 在集合组之间移动集合只改变逻辑层级；
- 集合树禁止循环引用。

### 延后能力

- 首期不实现由保存的搜索条件自动维护资产结果的智能集合；
- 首期不实现标签层级、父标签继承或标签同义词。

## 后果

- 数据模型需要区分 `CollectionGroup` 和 `Collection`；
- 集合树拖放与文件夹树拖放的命令语义不同；
- 大量标签的可用性依赖快速搜索、批量编辑和使用频率排序。
