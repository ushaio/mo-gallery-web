# ADR-0039：媒体后端与逐格式能力等级

- 状态：已接受（真实样本与发布环境验证仍待完成）
- 日期：2026-07-31
- 关联：ADR-0009、ADR-0010、ADR-0035、`verification-matrix.md`

## 背景

扩展名被扫描器识别，不等于能够读取尺寸、EXIF、生成缩略图或播放动画。媒体能力必须按实际解码链和证据分级，避免把占位建档宣传为完整格式支持。

## 决策

MVP 当前采用 Go 进程内媒体管线：

- Go 标准库 `image`、`image/jpeg`、`image/png`；
- `golang.org/x/image/webp` 与 `golang.org/x/image/tiff` 注册解码器；
- `github.com/rwcarlsen/goexif/exif` 提取当前可读取的 EXIF；
- 自有文件头探测、GIF 帧计数、方向处理和 JPEG 派生图生成；
- 512px 缩略图与 2048px 预览统一编码为 JPEG；
- 原文件和派生图只通过当前资源库、session 与资产 ID 校验后的同源 handler 提供。

当前不引入依赖系统 codec 的正式后端，也没有 HEIF/AVIF/RAW 原生解码器。前端已有的 `@jsquash/avif` 用于其他图片处理流程，不构成本地资源库后端的 AVIF 支持证据。

## 当前能力矩阵

| 格式 | 建档 | 尺寸/解码 | 512/2048 派生图 | EXIF | 当前等级 |
|---|---|---|---|---|---|
| JPEG/JPG | 是 | Go 标准库 | 是 | 当前 `goexif` 能力 | 代码支持，待真实矩阵验收 |
| PNG | 是 | Go 标准库 | 是 | 不承诺 | 代码支持，待真实矩阵验收 |
| WebP | 是 | `x/image/webp` | 是 | 不承诺 | 代码支持，待真实矩阵验收 |
| GIF | 是 | Go 首帧解码并统计帧数 | 静态首帧 | 不承诺 | 代码支持；动画交互/减少动态效果待验收 |
| TIFF | 是 | `x/image/tiff` 可解码的变体 | 可解码时生成 | 部分变体 | 实验性，未完成 8/16-bit 样本验证 |
| 静态 AVIF | 是 | 当前 Go 管线无解码器 | 否 | 否 | 占位建档，不是 ADR-0035 所要求的正式支持 |
| 动画 AVIF | 是 | 仅文件头识别 | 否 | 否 | 占位建档，明确不支持播放 |
| HEIC/HEIF | 是 | 当前 Go 管线无解码器 | 否 | 不承诺 | 占位建档 |
| CR2/CR3/NEF/ARW/DNG/RAF | 是 | 文件头/扩展名识别；无通用 RAW 预览提取器 | 通常否 | `goexif` 可读时部分提取 | 占位建档；未达到承诺的内嵌 JPEG 支持 |

“建档”表示保存路径、文件名、大小、修改时间和可读取元数据，并允许组织、移动、重命名、系统程序打开和重试预览。它不表示完整预览支持。

## 失败行为

遵循 ADR-0010：

- 解码失败仍保留同一资产记录；
- `preview_status` 标记为不可用并保存受限长度的错误；
- 网格显示占位状态，不把解码失败误报为文件失联；
- 单文件失败不终止扫描；
- 重试更新同一资产，不创建重复记录。

## 安全与资源限制

当前代码设置：

- 单次解码输入上限 256 MiB；
- 最大 180,000,000 像素；
- GIF 最大检查 10,000 帧；
- EXIF 字符串、JSON 和预览错误长度上限；
- 派生图任务按选中、可见、后台优先级调度，并在源文件变化时废弃旧结果。

这些限制仍需用畸形和超大真实样本验证。Go `image.Decode` 不能被视为已具备强制执行的解码超时；若 Spike 证明存在不可接受的卡死或内存风险，应改为可终止的隔离进程或受控原生后端。

## 正式支持的升级条件

某格式从占位或实验性升级为正式支持前，必须：

1. 使用多个真实设备/机型样本验证正常、旋转、无 EXIF、损坏和大尺寸文件；
2. 在无开发环境和额外 codec 的 Windows 10/11 x64 VM 中验证 Wails production build；
3. 验证方向、透明度、ICC/色彩限制和派生图输出；
4. 记录失败降级、资源上限、依赖许可证与打包体积；
5. 对 RAW 验证六类格式的最高可用内嵌 JPEG，不做 RAW 显影。

## 后果

- 当前可以安全组织无法预览的受支持扩展名文件；
- 产品文案不得宣称 AVIF、HEIC/HEIF 或 RAW 已完整支持；
- ADR-0009 和 ADR-0035 中高于当前能力矩阵的承诺仍是待实现需求；
- 后续替换或增加解码后端时，必须递增派生图 decoder/content version，使旧缓存可重建。
