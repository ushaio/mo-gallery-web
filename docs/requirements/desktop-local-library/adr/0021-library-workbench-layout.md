# ADR-0021：本地资源库工作台布局

- 状态：已接受
- 日期：2026-07-30

## 背景

本地资源库同时包含真实文件夹、集合、标签、筛选、资产网格、详情编辑、扫描进度和回收站。需要确定首期主页面的信息架构，保证用户能高频浏览和整理 10 万项资产，而不是堆叠多个装饰性卡片。

## 候选方案

### A. 三栏资源管理工作台（建议）

```text
┌──────────────┬──────────────────────────────────┬──────────────────┐
│ 库内导航     │ 工具栏 / 路径 / 筛选             │ 详情与批量编辑   │
│              ├──────────────────────────────────┤                  │
│ 全部资产     │                                  │ 预览             │
│ 收藏         │       虚拟化缩略图网格           │ 文件/EXIF         │
│ 文件夹树     │                                  │ 标签/评分/集合    │
│ 集合         │                                  │ 标题/备注         │
│ 标签         │                                  │                  │
│ 失联/失败    │                                  │                  │
│ 回收站       │                                  │                  │
└──────────────┴──────────────────────────────────┴──────────────────┘
```

- 全局 MO Gallery 侧栏保留“本地资源库”一级菜单；
- 进入后页面内部再提供当前资源库的库内导航；
- 中央网格支持缩略图尺寸、排序、筛选、框选、多选和拖放；
- 右侧详情面板可折叠，单选编辑资产，多选执行批量字段操作；
- 顶部显示当前资源库切换、相对路径、扫描状态和导入/上传命令。

优点：适合高频扫描、选择和整理，物理文件夹与逻辑组织都持续可见，接近成熟 DAM 工具。

代价：需要严格控制最小宽度和面板折叠，避免 1024px 窗口拥挤。

### B. 双栏浏览 + 弹窗详情

左侧库内导航，中间网格；详情通过弹窗或独立页面查看。

优点：中央网格空间更大，首期布局较简单。

代价：批量编辑和连续查看 EXIF/标签效率低，频繁开关弹窗。

### C. 文件夹页面、集合页面、详情页面分别路由

每种组织方式使用独立页面。

优点：单页职责较小。

代价：在文件夹、集合和标签之间整理资产时跳转频繁，拖放关系弱，不符合工作台式资源管理。

## 建议的交互约束

- 不在页面内部继续使用卡片套卡片；工具栏、导航、网格和详情面板采用连续工作区分隔；
- 当前真实路径始终可见，防止应用内导入时目标不明确；
- 文件夹和集合使用不同图标、分组标题及拖放反馈；
- 文件操作显示实际动词，如“移动到文件夹”“移到资源库回收站”；
- 10 万项网格必须保持稳定尺寸并虚拟化，加载/选择状态不能改变网格轨道尺寸；
- 右侧面板在窄窗口可折叠或覆盖显示，但不得遮挡删除确认等模态层。

## 决策

采用 **方案 A：三栏资源管理工作台**。

- 全局 MO Gallery 侧栏新增“本地资源库”一级入口；
- 页面左栏显示当前资源库的全部资产、收藏、真实文件夹树、集合、标签、失联资产、预览失败和回收站；
- 中央区域为虚拟化资产网格，上方持续显示当前真实相对路径、搜索、筛选、排序、缩略图尺寸和主要命令；
- 右侧详情面板可折叠，单选时显示预览与完整字段，多选时切换为批量编辑；
- 当前资源库切换、扫描/预览任务状态在工作台顶部可见；
- 1024px 窗口下允许折叠右侧详情和收窄库内导航，但中央网格不得被固定面板挤出可用空间。

## 后果

- 页面内部形成独立资源管理工作台，不把库内导航项加入全局路由侧栏；
- 文件夹、集合和标签必须使用不同图标、分组和拖放状态；
- 选择状态、加载状态和缩略图生成不得改变网格单元尺寸；
- 需要支持中央网格与右侧详情之间的稳定选择同步，以及多选批量编辑语义；
- 不采用卡片嵌套式页面结构。
