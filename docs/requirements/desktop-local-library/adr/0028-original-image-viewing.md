# ADR-0028：原图查看模式

- 状态：已接受
- 日期：2026-07-30

## 背景

用户需要直接查看原图，以检查细节。默认在详情栏直接解码每个原文件会给高像素 JPEG、巨型 TIFF 和快速切片带来明显内存/I/O 压力；RAW 原文件还不能在“不做显影”的边界下直接显示。

## 候选方案

### A. 默认屏幕预览，显式进入原图/100% 模式（建议）

- 单击资产后优先显示 2048px 屏幕预览，保证切片速度；
- 用户双击、点击“查看原图”或缩放超过预览能力时，按需读取原文件；
- 支持适应窗口、实际像素 100%、放大缩小、拖动画布和前后切换；
- 对超大 JPEG/PNG/TIFF，优先使用分块/降采样解码，避免一次性把完整位图放进 WebView 内存；
- JPEG/PNG/WebP/HEIC/TIFF 在解码器支持时进入原图模式；
- RAW 的“原图查看”实际显示文件内可用的最高分辨率内嵌预览，并明确标注“RAW 内嵌预览”，不声称是显影后的原始像素；
- 无法内嵌查看时提供“使用系统默认程序打开”。

优点：兼顾快速浏览和细节检查，格式边界诚实，适合大型照片库。

代价：需要两级加载状态、缩放查看器和超大图内存治理。

### B. 对可解码格式始终直接显示原文件

优点：用户无需切换模式，看到的就是原文件解码结果。

代价：切换大图时慢且占用大量内存；RAW 仍必须例外；不适合详情栏连续选片。

### C. 只显示生成的屏幕预览，不提供原图模式

优点：性能最可控。

代价：无法进行像素级细节检查，不符合照片管理工具需求。

## 建议的不变量

- “查看原图”只读，不修改原文件；
- 受控的 Go 资源读取接口必须验证路径属于当前资源库，前端不能读取任意 `file://` 路径；
- 原图读取失败不会改变资产索引状态；
- 原图查看和“使用系统程序打开”是两个不同动作；
- RAW 内嵌预览必须在 UI 中明确标注，不能误导为 RAW 显影。

## 决策

采用 **方案 A：默认屏幕预览，显式进入原图/100% 模式**。

- 单击资产优先显示 2048px 屏幕预览；
- 双击、点击“查看原图”或进入高倍率时按需读取原文件；
- 支持适应窗口、100% 实际像素、缩放、拖动画布和前后切换；
- JPEG/PNG/WebP 读取原文件，HEIC/TIFF 在解码器支持时读取原文件；
- RAW 显示最高可用内嵌 JPEG，并明确标注“RAW 内嵌预览”，不执行或暗示 RAW 显影；
- 超大图片采用分块、降采样或其他受控解码策略，避免一次性向 WebView 传输完整位图；
- 另提供“使用系统默认程序打开”，该动作不同于应用内原图查看。

## 后果

- 查看器需要两级加载状态，并在预览升级为原图时保持缩放/选择稳定；
- Go 侧资源读取接口只允许当前资源库内的已索引资产路径；
- 原图读取失败只影响查看，不把资产改成失联或预览不可用；
- RAW 查看界面始终显示内嵌预览提示。
