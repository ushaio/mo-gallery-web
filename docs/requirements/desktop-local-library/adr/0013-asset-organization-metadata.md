# ADR-0013：首期资产组织元数据

- 状态：已接受
- 日期：2026-07-30

## 背景

已确定文件夹、集合和标签三种组织结构，但单张资产还可能需要评分、颜色标记、收藏、标题和备注。首期字段会直接影响数据库、筛选器、批量操作和详情面板。

所有组织元数据只写入 `.mo-gallery/library.db`，不修改原文件名、EXIF、IPTC 或 XMP。应用内重命名文件是独立的磁盘命令，不能与“修改显示标题”混为一谈。

## 候选方案

### A. 完整基础整理字段（建议）

- 标签：多值，可批量添加/移除；
- 集合：多对多关系；
- 评分：0 至 5 星；
- 颜色标记：无、红、黄、绿、蓝、紫；
- 收藏：布尔快捷标记；
- 显示标题：可选，不修改文件名；
- 备注：可选纯文本；
- 自动只读元数据：文件名、相对路径、格式、大小、尺寸、拍摄时间、相机、镜头、曝光参数和 GPS（可读取时）。

优点：覆盖照片筛选、初选和主题整理的常见流程，接近资产管理工具的基础能力。

代价：详情面板、批量编辑和组合筛选范围较大。

### B. 精简整理字段

只提供标签、集合、收藏和自动只读元数据；评分、颜色、标题和备注后续增加。

优点：首期界面和模型更小。

代价：摄影初选和分级流程不足，后续增加字段会改动筛选与批量操作。

### C. 在 A 基础上写入 XMP sidecar

除数据库外，为 RAW 等文件生成 `.xmp`，让评分、标签可被其他摄影软件读取。

优点：跨软件互操作更好。

代价：会在照片目录产生额外文件，需要冲突合并、监听排除和外部修改同步；不建议首期默认实现。

## 决策

采用 **方案 A：完整基础整理字段**。

### 用户可编辑字段

- 标签：多值，支持批量添加和移除；
- 集合：多对多关系；
- 评分：整数 0 至 5，`0` 表示未评分；
- 颜色标记：无、红、黄、绿、蓝、紫，单选；
- 收藏：独立布尔值，不与五星评分互相推导；
- 显示标题：可选文本，不修改文件名；
- 备注：可选纯文本。

### 自动只读字段

- 文件名、相对路径、扩展名/MIME、文件大小、修改时间；
- 图片宽高、方向和预览状态；
- 拍摄时间、相机厂商/型号、镜头、焦距、光圈、快门、ISO；
- GPS 经纬度及海拔（原文件存在且可读取时）。

### 持久化边界

- 所有用户整理字段只写入 `.mo-gallery/library.db`；
- 首期不生成或修改 XMP sidecar；
- 不写回原文件 EXIF、IPTC 或其他元数据；
- 应用内文件重命名是独立磁盘命令，不由显示标题隐式触发。

## 后果

- 网格、筛选栏和详情面板需支持评分、颜色、收藏、标签和集合的组合操作；
- 批量编辑只修改用户明确选定的字段，空值不能被误当作批量清除；
- 集合、标签、标题、备注、评分和颜色属于不可从原文件重建的数据，必须纳入数据库备份/迁移验证；
- GPS 默认只在本地展示和筛选；上传时是否携带由现有上传流程及后续集成决策决定。
