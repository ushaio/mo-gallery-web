# ADR-0001：本地资源库的认证与离线边界

- 状态：已接受
- 日期：2026-07-30

## 背景

当前 Desktop 的 `AdminLayout` 整体受 `ProtectedRoute` 保护。用户没有有效服务端登录时，只能停留在登录页。但“本地资源库”从领域上管理本机文件，不天然需要服务端身份。

## 决策驱动因素

- 无网络或服务端不可用时是否仍应浏览和整理照片；
- 是否接受为本地功能强制登录；
- 本地资产与线上账号的数据归属；
- 对当前路由、布局、认证上下文的改造范围。

## 候选方案

### A. 本地资源库完全离线可用（建议）

将应用壳和本地资源库移出服务端认证边界；线上页面继续要求登录。用户未登录时仍能进入本地资源库，上传/线上相册等动作再触发登录。

优点：符合“本地”心智，服务端故障不阻断本地工作，可自然形成 local-first 架构。

代价：需要拆分当前全局 `ProtectedRoute`，明确离线导航状态和登录后回跳。

### B. 保持全应用登录后可用

本地资源库继续放在现有 `ProtectedRoute` 内。

优点：改造最少，账号模型统一。

代价：本地文件管理被不必要地绑定网络与服务端，偏离 Billfish/Pixcall 类产品体验。

### C. 首期要求登录，后续再离线化

短期按 B 实现，预留后续拆分。

优点：可能降低首期 UI 改造。

代价：数据归属和服务接口容易先按账号耦合，后续迁移成本通常高于一开始划清边界；不建议作为默认方案。

## 决策

采用 **方案 B：保持全应用登录后可用**。本地资源库继续位于现有服务端认证边界内；没有有效登录状态时不能进入。

补充边界：该决策只约束访问入口，不代表将本地索引存入服务端。绝对路径、缩略图缓存和本地组织数据默认仍应落在本机专用数据库中，以免污染现有 PostgreSQL/Prisma 线上模型。

## 预期后果

- 首期无需拆分 ProtectedRoute 和匿名应用壳。
- 登录过期、服务端不可达或账号不可用时，本地资源库也不可访问。
- 本地资源库入口继承当前账号会话，但本地索引不应因此复用线上 Photo 表。
- 需明确同一台电脑切换账号时，本地资源库是机器共享还是账号隔离；该问题留待后续访谈。
