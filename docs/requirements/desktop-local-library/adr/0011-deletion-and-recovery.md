# ADR-0011：应用内删除与恢复语义

- 状态：已接受
- 日期：2026-07-30

## 背景

应用内移动和重命名会实际修改磁盘原文件，因此“删除”也必须定义磁盘行为。资源管理器外部删除仍会由一致性扫描表现为失联资产；本 ADR 只决定 MO Gallery Desktop 内发起的删除。

## 候选方案

### A. 资源库内置回收站（建议）

删除资产时，将原文件移动到资源库保留目录中的回收区，并将资产记录标记为已回收。恢复时移回原相对路径并恢复同一资产 ID、标签、评分和集合关系；只有“永久删除”才真正删除文件和记录。

建议布局：

```text
.mo-gallery/
└─ trash/
   └─ files/<asset-id>/<original-name>
```

优点：文件与组织数据可一起恢复；行为跨平台一致；回收内容随整个资源库迁移；不依赖操作系统回收站 API。

代价：回收文件仍占资源库磁盘空间；必须处理原路径已被占用、只读库和清空回收站失败。

### B. 使用操作系统回收站

将原文件送入 Windows/macOS 系统回收站，索引保留为已删除或失联。

优点：符合系统习惯，资源库本身不保存回收文件。

代价：跨平台 API 和恢复定位不一致；应用难以保证恢复原资产关系；资源库迁移不包含已删除文件。

### C. 应用内直接永久删除

确认后删除原文件及资产记录。

优点：实现和空间语义最简单。

代价：误操作不可恢复，不适合作为照片资产管理工具的默认删除行为。

## 建议的不变量

- “删除”默认不得永久擦除原文件；
- 批量永久删除必须二次确认并显示文件数量和总大小；
- 文件操作失败时不得把资产记录伪装成已成功删除；
- 外部删除不会自动进入应用回收站，而是产生失联资产；
- 删除文件夹时必须先明确其包含的资产数量，不允许仅删除目录记录。

## 决策

以 **方案 A：资源库内置回收站** 为默认行为，同时在应用内删除流程中提供显式的“永久删除”选项。

### 正常资产不提供“移除出库”

本地资源库本质上管理资源库目录树中的真实文件：

- 正常可用资产不提供“只删除索引但让文件继续留在库内”的操作；
- 只要受支持文件仍位于资源库目录树中，扫描或 watcher 就应将其纳入资源库管理范围；
- 用户若希望文件不再由该资源库管理，应通过系统文件资源管理器将文件移出资源库边界；
- 文件被外部移出后，原记录按 ADR-0029 成为失联资产；此时才可显式“移除失联记录”；
- “移除失联记录”不是正常资产删除方式，不操作任何仍存在的库内文件。

### 默认删除：放入资源库回收站

- 默认主操作是“移到资源库回收站”；
- 原文件移动到 `.mo-gallery/trash/files/<asset-id>/`；
- 资产进入已回收状态，保留原相对路径、标签、评分、集合关系和索引信息；
- 恢复时沿用同一资产 ID；若原路径已被占用，要求用户选择新名称或目标文件夹；
- 回收站中的资产不出现在普通网格和普通搜索结果中，只在回收站视图显示。

### 可选删除：永久删除

- 删除确认界面提供“永久删除”危险操作，但不得作为默认焦点或默认回车动作；
- 永久删除原文件、资产记录、集合/标签关系和对应缩略图，不进入应用或系统回收站；
- 批量永久删除必须显示资产数量和可计算的总大小，并再次确认不可恢复；
- 对 `missing` 资产执行永久删除时，只清理索引和组织关系，不声称删除一个已经不存在的磁盘文件；
- 永久删除过程中任一文件失败时，记录必须反映逐项真实结果，不得把整批资产全部标记成功。

### 文件夹删除

- 本节的早期“逐项回收资产”方案已由 ADR-0033 修订；
- 删除非空文件夹时，确认界面分别显示受管理资产、其他文件、目录数和总大小；
- 选择回收站时，将完整目录树作为一个批次移动，不能拆散未索引或不支持的伴随文件；
- 选择永久删除时，对整个目录树应用同等的危险确认和逐项失败语义；
- 不将 `.mo-gallery` 暴露为可删除的普通文件夹。

## 后果

- UI 至少需要普通资产视图、资源库回收站视图、恢复、永久删除和清空回收站；
- 文件状态和数据库状态必须通过可恢复的文件操作事务/任务协调；
- 应用外删除仍不进入资源库回收站，只形成失联资产；
- 回收站占用应计入资源库空间统计。
