# ADR-0012：创建资源库与接管现有文件夹

- 状态：已接受
- 日期：2026-07-30

## 背景

一个资源库就是包含 `.mo-gallery` 数据的普通文件夹。首次使用时，需要明确能否把已经装有照片的现有文件夹初始化为资源库，以及“打开资源库”和“创建资源库”的区别。

## 候选方案

### A. 既可创建新库，也可将现有文件夹初始化为资源库（建议）

- **创建资源库**：选择一个空文件夹或新建文件夹，写入 `.mo-gallery` 后打开；
- **将文件夹设为资源库**：选择一个尚无 `.mo-gallery` 的现有文件夹，预扫描后显示支持文件数量与预计处理规模，经确认后创建清单/数据库并开始索引；
- **打开资源库**：只接受已经包含有效 `.mo-gallery/library.json` 的文件夹。

优点：用户可以直接接管已有照片目录，也不会把普通文件夹和已有资源库混为一个含糊动作。

代价：需要预扫描、嵌套库检查和初始化失败回滚。

### B. 只能使用空文件夹创建资源库

用户必须先创建空库，再通过应用内导入把照片移动进去。

优点：路径和导入行为最可控。

代价：已有大型照片目录必须整体搬迁，成本高且没有必要。

### C. “打开文件夹”自动初始化

选择任何文件夹；若没有 `.mo-gallery`，应用自动创建并扫描。

优点：步骤最少。

代价：用户可能只是选错目录却留下隐藏元数据；系统根目录、用户主目录或包含其他资源库的上级目录风险很高。

## 建议的不变量

- 禁止将磁盘根目录、用户主目录、系统目录和应用安装目录直接初始化为资源库；
- 禁止资源库嵌套：新库根目录不能位于现有库中，也不能包含另一个资源库；
- 初始化失败时不得留下一个看似有效但数据库不完整的资源库；
- 现有 `.mo-gallery` 若无效或版本不兼容，应进入修复/报错流程，不得覆盖；
- 初始化现有文件夹只创建索引与缩略图，不移动其中已有照片。

## 决策

采用 **方案 A：既可创建新库，也可将现有文件夹初始化为资源库**。

提供三个含义不同的入口：

1. **创建资源库**：选择空文件夹或新建文件夹，验证后创建 `.mo-gallery`；
2. **将文件夹设为资源库**：选择已有内容但尚未成为资源库的文件夹，预扫描并确认后初始化；（首次扫描期间的可用性由 ADR-0034 决定）
3. **打开资源库**：只打开已有有效 `.mo-gallery/library.json` 的文件夹，不执行隐式初始化。

初始化现有文件夹时，照片保持原位，只创建索引和缩略图。

### 禁止嵌套资源库

在创建或初始化前，应用必须同时执行双向检查：

- **向上检查**：候选目录的任一父路径只要存在有效资源库清单，就拒绝创建，避免在已有资源库中建立子资源库；
- **向下检查**：候选目录的任一后代目录只要存在有效资源库清单，也拒绝创建，避免把已有资源库包进更大的父资源库；
- 检查使用规范化后的真实路径，处理 `.`、`..`、Windows 路径大小写、符号链接和 junction/reparse point，不能只比较原始字符串前缀；
- 默认不跟随指向资源库目录树之外的符号链接或 junction 扫描资产，避免间接形成跨库引用和循环遍历；
- 已损坏或无法读取的 `.mo-gallery` 也按潜在资源库冲突处理，要求用户先修复或显式移走，不能直接覆盖。

### 初始化事务

- 预扫描阶段不写入候选目录；
- 用户确认后先在临时保留目录中创建并验证清单和数据库；
- 初始化成功后再原子提交为 `.mo-gallery`；
- 失败时清理临时文件，不留下可被误识别为有效库的半成品。

## 后果

- 可直接接管已有大型照片目录，无需搬迁原文件；
- “打开”和“初始化”必须是不同命令，避免误写普通目录；
- 路径验证需要平台相关实现和 junction/符号链接测试；
- 资源库目录树形成严格边界，不允许直接或间接嵌套。
