# ADR-0019：首期目标操作系统

- 状态：已接受，按阶段交付（经 Round 20 修订）
- 日期：2026-07-30

## 背景

资源库涉及文件监听、原子移动、路径规范化、符号链接/junction、文件锁、HEIC/RAW 解码库打包和缩略图缓存。上述能力具有平台差异。当前发布工作流只在 `windows-latest` 构建 Wails `.exe`，没有 macOS 或 Linux Desktop 制品。

## 候选方案

### A. 首期只正式支持 Windows（建议）

- 验收 Windows 10/11 x64；
- 路径、NTFS 大小写行为、junction/reparse point、长路径和 Defender/文件占用纳入测试；
- 解码和监听依赖只需先保证 Windows 打包；
- 服务接口保持平台抽象，避免阻断未来 macOS 支持，但不把未测试平台声明为可用。

优点：符合当前发布事实，能集中完成可靠的文件系统语义和格式支持。

代价：macOS 摄影用户首期无法使用正式版本。

### B. 首期支持 Windows + macOS

优点：覆盖主要摄影工作平台。

代价：需要新增签名/公证/构建流水线，并验证 APFS 路径、FSEvents、包内原生解码依赖和应用权限；范围明显扩大。

### C. 首期支持 Windows + macOS + Linux

优点：平台覆盖最广。

代价：原生 WebView、HEIC/RAW 依赖、桌面集成和发行矩阵最大，不符合当前仅 Windows 发布基础。

## 建议的不变量

- 资源库清单和 SQLite schema 使用平台无关格式；
- 数据库保存 `/` 分隔的规范相对路径，在系统边界转换为原生路径；
- 不把 Windows 盘符或绝对路径写入库内资产记录；
- 平台相关文件操作放在独立适配层，不散落到领域服务；
- 在未验证平台上打开资源库不得修改格式版本。

## 决策

采用分阶段平台策略：**当前实现阶段正式支持 Windows；macOS 是后续正式发布目标，不作为当前 Windows 开发阶段的硬性交付门槛**。

- 当前阶段验收和发布范围为 Windows 10/11 x64；
- Windows 验证 NTFS 路径、junction/reparse point、长路径、跨卷移动和文件占用；
- 当前代码结构需保留 macOS 适配边界，但没有 macOS 开发/测试环境时不要求本阶段完成构建、签名、公证或真实设备验收；
- 后续 macOS 阶段再验证 APFS、符号链接、跨卷移动、文件监听、应用目录权限及 HEIC/RAW 原生依赖；
- 资源库清单、SQLite schema、规范相对路径和缩略图格式从当前阶段起保持平台无关，避免阻断后续 Windows/macOS 迁移；
- 平台特定文件系统能力通过适配层实现，不进入领域模型。

## 发布要求

- 当前阶段沿用并完善 Windows 构建；
- 后续正式分发 macOS 时新增 CI、Developer ID 签名和 Apple 公证；
- 签名或公证凭据只通过 CI secrets 提供，不进入仓库；
- 未签名的开发构建不能作为“正式支持 macOS”的验收制品；
- 最低 macOS 版本和 Intel/Apple Silicon 架构范围由 ADR-0020 决定。

## 后果

- 当前阶段不得在发行说明中宣称 macOS 已受支持；
- 所选 HEIC/RAW 方案仍需提前评估 CGO、动态库分发、许可证和未来双架构可行性；
- 平台之间路径大小写差异可能造成迁移冲突，开库时需要兼容性检查；
- 后续 macOS 验收通过后，才可将其状态从“计划支持”改为“正式支持”。
