# ADR-0031：RAW+JPEG 同名配对

- 状态：已接受
- 日期：2026-07-30

## 背景

相机常同时生成同目录、同主文件名的 RAW 与 JPEG，例如 `DSC_0001.ARW` 和 `DSC_0001.JPG`。两者是独立磁盘文件。直接建模成一个组合资产，会让路径身份及移动、删除、上传产生歧义。

## 决策

采用“独立资产为基础，可选合并显示为扩展”的方案。

### 基础模型

- RAW 和 JPEG 各自按相对路径建立资产，拥有独立资产 ID 和组织数据；
- 移动、重命名、删除和上传默认只作用于用户明确选择的文件；
- 不因同名而物理合并、自动删除或迁移组织数据；
- MVP 网格仍可分别显示两个资产。

### 扩展：RAW+JPEG 合并显示

- 后续提供资源库级或用户级开关；
- 同一真实文件夹、同主文件名且恰好一个 JPEG 与一个受支持 RAW 时建立可重建的展示配对；
- JPEG 作为网格主项，RAW 不再占普通网格项；
- JPEG 详情栏显示关联 RAW 的文件名、格式、大小、路径与操作入口；
- RAW 仍是已索引的独立资产；关闭开关后恢复分别显示；
- 任一文件移动、改名、删除或出现多文件歧义时解除配对，RAW 必须重新显示；
- 合并显示不等于重复文件合并，也不得自动联动删除。

## 延后事项

组级移动、重命名、删除、上传、组织字段传播、筛选计数和手动配对在扩展实施前另行定义。Live Photo 与 XMP sidecar 不纳入本决策。
