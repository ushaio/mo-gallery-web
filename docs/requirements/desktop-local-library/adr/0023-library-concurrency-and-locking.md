# ADR-0023：资源库并发打开与写入锁

- 状态：已接受（经访谈修订）
- 日期：2026-07-30

## 背景

资源库可位于本机磁盘、外接硬盘或用户自行放置的目录。两个 MO Gallery Desktop 进程、两台机器经共享盘，或应用异常退出后的残留锁，都可能导致同一资源库被同时打开。SQLite 的数据库锁不能协调两个文件监听器、缩略图任务和原文件移动命令。

## 候选方案

### A. 单写者锁，冲突时只读打开或取消（建议）

- 打开资源库时在 `.mo-gallery` 获取库级独占写锁；
- 获得锁的实例可以扫描、监听、编辑元数据和执行文件命令；
- 锁已被其他有效实例持有时，用户可选择只读打开或取消；
- 只读模式允许浏览已有索引与缩略图，不启动文件监听、校准、预览生成，不允许导入、移动、重命名、删除或编辑组织数据；
- 锁记录包含库 ID、进程 ID、主机标识和启动时间，作为诊断信息；是否有效必须结合操作系统锁判断，不能仅信任文件内容；
- 异常退出后由操作系统释放锁，残留诊断文件可安全重建。

优点：防止多个写入者同时修改文件和索引；用户在冲突时仍可查看已有数据；规则适合未来跨平台适配。

代价：只读模式需要完整的 UI 禁用状态；网络共享文件系统上的锁语义仍需限制和测试。

### B. 锁冲突时完全拒绝打开

优点：行为最安全、实现比只读模式小。

代价：用户无法在第二个窗口查看照片，错误体验更硬；需要找到并关闭原实例。

### C. 允许多个实例读写

优点：用户限制最少。

代价：监听、移动、索引和任务队列会发生竞态，不能只靠 SQLite WAL 保证领域一致性，不接受。

## 建议的不变量

- 一个资源库同一时间最多一个写入者；
- 切换资源库前必须释放当前库锁；
- 应用不能通过删除其他实例的锁文件强行抢占仍有效的锁；
- 首期不声明支持 NAS/网络共享盘上的多机并发写入；
- 外接盘意外断开时停止写入任务并进入错误状态，不在重新挂载前继续使用旧文件句柄。

## 决策

正常产品流程不允许应用多开，采用两层防护：

### 第一层：应用全局单实例

- 使用 Wails v2.12 已提供的 `options.SingleInstanceLock`；
- 第二次启动时不创建第二个可操作实例；
- 回调中显示、取消最小化并聚焦已有主窗口；
- 后续若支持通过命令行/系统关联打开资源库，可把第二次启动参数转发给已有实例处理；
- 单实例约束适用于整个 MO Gallery Desktop，而不只是本地资源库页面。

### 第二层：资源库独占写保护

- 资源库打开时仍获取 `.mo-gallery` 库级独占写锁，防止同一外接盘或共享目录被另一台电脑/异常实例同时写入；
- 库锁冲突时直接拒绝以当前实例打开该库，并提示库可能正在其他设备或进程中使用；
- 首期不实现只读打开模式；
- 锁有效性依赖操作系统锁，诊断文件内容不能作为唯一依据；
- 应用异常退出后操作系统应释放锁，残留诊断信息不能永久阻塞资源库。

## 后果

- 用户正常情况下不会看到“第二个实例只读打开”的复杂选择；
- 需要在 `main.go` 配置 Wails 单实例锁，并验证最小化、后台和第二次启动行为；
- 库级锁仍是必要的数据安全不变量，尤其针对可迁移资源库；
- 锁冲突时不能通过删除文件强制抢占仍有效的锁；
- 首期不声明支持 NAS/网络共享盘上的多机读写。
