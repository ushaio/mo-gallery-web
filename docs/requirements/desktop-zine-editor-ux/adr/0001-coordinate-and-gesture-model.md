# ADR-0001：采用跨页坐标与手势提交模型

- 状态：已接受
- 日期：2026-08-03

## 背景

Zine 编辑器的拖动、缩放和旋转存在不跟手、控制框错位与松手回弹风险。现有实现把槽位保存为 `page + 单页 x/y`，并在 Moveable 回调中混合 DOM 临时样式、React 状态、像素到毫米换算和自动保存。当对象跨过书脊时，单页坐标还会产生归属切换和坐标跳变。

## 决策

采用以下组合：

1. 槽位几何统一使用跨页坐标；`page` 仅作为派生/导出语义，不作为移动边界。
2. 手势开始时捕获初始快照；手势期间只更新本地 draft geometry 和 DOM。
3. 手势结束时执行归一化、轻量吸附和边界处理，然后一次性提交到 Zustand。
4. 每个完整手势只产生一个 undo 步骤；无变化不入历史。
5. 画布普通滚轮用于平移，Ctrl/Cmd+滚轮以指针为中心缩放，空格拖动作为备用平移手势。
6. 单击选中、双击进入图片裁切或文字编辑；编辑态与几何手势互斥。文字编辑点击外部或 Esc 提交；图片裁切点击外部提交，Esc 取消并恢复进入裁切态前的构图。

## 未采用的方案

### A. 每帧写入全局状态

放弃原因：会让 Zustand 订阅者、缩略图和保存调度参与高频指针事件，增加延迟和状态竞争。

### B. 继续使用单页坐标并在跨页时切换 page

放弃原因：对象跨越书脊时需要重写坐标，容易出现跳变；无法表达单一跨页对象。

### C. 仅显示轮廓、松手后再渲染内容

放弃原因：与轻量 Canva 定位不符，用户需要看到内容实时跟随指针。

## 后果

- 需要调整 `Slot` 类型、`slot-render`、Moveable 适配和 PDF/缩略图渲染。
- 需要单独实现 `GestureSession` 或等价 hook，禁止组件各自维护不同的几何换算。
- 需要补充跨书脊、出血区、缩放中心、撤销粒度和图片裁切的回归测试。
- 未来实现多选、对齐和组合时，可继续复用跨页坐标体系。
