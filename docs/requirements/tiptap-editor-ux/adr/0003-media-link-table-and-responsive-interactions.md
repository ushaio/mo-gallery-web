# ADR-0003：统一媒体、链接、表格与窄屏交互

- 状态：暂定接受（访谈超时采用推荐项）
- 日期：2026-08-04

## 背景

当前图片 URL 输入、文件粘贴、媒体链接转换和宿主照片面板分属不同入口；链接只提供简单 URL 输入；表格固定插入 3x3；窄屏主要依赖固定工具栏横向滚动。这些行为缺少统一的状态、错误恢复和触控策略。

## 决策

1. 图片以本地文件/素材上传为主路径，URL 插入为次级路径。
2. 文件选择、拖放和粘贴统一经过 FileHandler 风格的入口与同一上传会话。
3. 上传立即插入占位，显示进行中、失败和可恢复状态；失败允许重试、替换或删除，不丢失相邻内容和选区。
4. 链接统一使用 Popover：支持创建、编辑、移除、复制与打开，并做协议补全和危险协议拒绝。
5. 表格插入使用网格选择行列；选中表格/单元格后显示上下文工具，覆盖增删行列、表头切换、合并、拆分和删除。
6. 窄屏只保留紧凑主工具栏；插入、格式和更多菜单使用底部面板承载，文本 Bubble Menu 仅保留少量高频命令。
7. Desktop 与 Web 共享交互状态机；文件选择器、上传 API 和底层路径能力由 runtime/宿主适配。

## 未采用的方案

### A. URL 图片作为主入口

放弃原因：与项目照片叙事场景不符，也无法提供稳定的上传进度、资源归属和失败恢复。

### B. 表格只调整入口、不补上下文命令

放弃原因：用户插入后仍无法完成常见结构修改，功能可发现性问题没有真正解决。

### C. 窄屏继续横向滚动完整工具栏

放弃原因：触控下命令位置不稳定，溢出状态不可见，且与分层命令架构冲突。

## 后果

- 需要新增统一上传会话与上传占位节点/decoration，并由 runtime 注入上传实现。
- 需要将图片、链接和表格编辑从主编辑器局部状态拆出为节点/浮层控制器。
- 需要底部面板组件及焦点恢复、软键盘和安全区适配。
- 需要验证 FileHandler 与现有故事链接、媒体链接 paste 规则的优先级。
