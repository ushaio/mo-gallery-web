# ADR-0005：主工具栏命令条支持横向滚动

- 状态：已接受（用户明确要求）
- 日期：2026-08-05
- 关联：ADR-0001 选项 A 的放弃原因、ADR-0003 选项 C、spec.md 成功标准 1

## 背景

主工具栏在窄屏下通过隐藏/迁移按钮（`hidden sm:flex`、`hidden lg:flex` 等）控制密度，
低频命令收敛进“格式/更多”菜单。用户反馈希望工具栏本身支持横向滚动，使全部命令常驻可达。

此前设计（spec 成功标准 1）明确“新用户不依赖横向滚动”，ADR-0003 选项 C 也否决了
“窄屏继续横向滚动完整工具栏”。本次由产品方明确要求变更该决策，本文档记录新决策并说明保留项。

## 决策

1. 主工具栏拆为“命令条 + 固定操作组”两段：
   - 命令条（块类型、字体/字号、行内格式、列表、引用、对齐、清除格式）水平方向 `overflow-x-auto`，
     空间不足时滚动；按钮命令取消按断点隐藏，保持常驻。
   - 插入、格式、撤销、重做固定在右侧（`shrink-0`），不随命令条滚动，避免菜单浮层被滚动容器裁切。
2. 字体、字号与重做常驻工具栏：字体/字号随命令条滚动（无断点隐藏），重做固定在右侧。
   格式菜单只保留工具栏没有的命令（首字下沉、文字颜色、背景颜色），消除重复入口。
3. 滚动条隐藏（`.tiptap-toolbar-scroll`：`scrollbar-width: none` + WebKit `::-webkit-scrollbar { display: none }`），
   滚动能力保留；不占空间、不分散注意力。
4. 键盘契约不变：Alt+F10 聚焦工具栏，方向键/Home/End 在 fieldset 内移动，焦点自动滚入视口。

## 未采用的方案

### A. 整个 fieldset 作为滚动容器

放弃原因：插入/格式 Popover 面板绝对定位在工具栏内，滚动容器会裁切面板或使面板随内容滚动，
破坏浮层交互与“菜单不出界”的契约。

### B. 保留断点隐藏 + 叠加滚动

放弃原因：隐藏后各断点下的可见内容都能放下，滚动条永远不会触发，等于没有实现需求。

### C. 显示细滚动条（初版实现）

放弃原因：用户要求不显示滚动条；细滚动条仍占据视觉空间并暴露溢出状态。
改为隐藏滚动条、仅保留滚动行为（触控滑动、触控板、Shift+滚轮）。

## 后果

- spec.md 成功标准 1 更新为：核心命令常驻命令条，空间不足时横向滚动；插入/格式/撤销重做固定可达。
- 验证矩阵“主工具栏”行更新为“命令条可横向滚动，固定组不裁切”。
- 后续如需进一步降低密度，优先考虑分组折叠，而非重新引入断点隐藏。

> 更新（2026-08-05 后续）：应产品反馈，格式菜单不再重复工具栏命令——斜体/下划线/删除线/行内代码/列表/引用/对齐/清除格式/重做从 `format` 命令面移除，字体/字号改为命令条常驻（滚动可达），格式菜单仅剩首字下沉、文字颜色、背景颜色。命令注册表成为唯一入口来源，避免同一命令双入口的行为漂移。
