# ADR-0004：统一粘贴、保存反馈、AI 上下文入口与内容兼容策略

- 状态：暂定接受（访谈超时采用推荐项）
- 日期：2026-08-04

## 背景

编辑器当前包含保留粘贴样式的自定义扩展，Story/Blog 宿主各自展示保存与草稿状态，AI 使用固定侧栏，历史内容同时存在 HTML、Tiptap JSON 和自定义节点。体验优化如果不先定义这些边界，容易造成外来样式污染、保存反馈重复、AI 入口冲突或旧内容破坏。

## 决策

1. 外部粘贴默认保留语义结构：标题、段落、列表、引用、代码、链接和基础粗体/斜体/下划线等 marks。
2. 默认清理来源字体、字号、颜色、背景色、行高、边距、绝对定位、布局容器和不受支持的内联样式。
3. 项目内部复制粘贴通过自有 MIME 或可识别 Tiptap JSON 保留完整受支持格式与自定义节点。
4. 宿主向共享编辑器注入 `SaveState`，编辑器统一展示 `saved`、`saving`、`dirty`、`error` 与重试动作；真正的自动保存、发布和草稿恢复仍由宿主拥有。
5. AI 固定侧栏是会话和结果工作区；上下文菜单只提供“针对选区/当前块使用 AI”等快捷动作，执行后展开侧栏并携带上下文。
6. 文档 schema 采用增量演进。旧节点继续可解析；归一化在读取后的编辑边界或保存前进行，不做无回滚的一次性破坏迁移。
7. 保存的 JSON 顶层或宿主记录中增加明确的 schema/version 信息；未知节点和属性必须有可观测的降级策略。

## 未采用的方案

### A. 尽量完整保留所有外部视觉样式

放弃原因：会把不受控 CSS、字体和布局带入叙事内容，造成 Web/Desktop 与阅读态不一致。

### B. 编辑器完全不感知保存状态

放弃原因：Story/Blog 当前已有相似但分散的状态，统一展示可减少跨宿主差异并让编辑区状态更清晰。

### C. AI 命令与普通 Slash 命令完全混排

放弃原因：AI 是异步会话与任务，不应伪装成普通同步编辑命令；侧栏仍需承担进度、结果、撤销与错误恢复。

### D. 一次性批量迁移所有历史内容

放弃原因：内容量、旧节点组合和 HTML/JSON 双存储存在不确定性，破坏性批量迁移风险过高。

## 后果

- 需要重构 `PastedStyleMark`/`PastedBlockStyle`，区分外部粘贴与项目内部粘贴。
- `NarrativeTipTapEditorProps` 或 runtime 需要新增保存状态契约。
- AI 快捷入口需要统一的上下文载荷与侧栏展开 API。
- 需要建立 schema fixture、旧文档回放、归一化幂等与读取态一致性测试。
