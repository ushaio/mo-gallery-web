# ADR-0001: Desktop 缓存页边界与清理行为

- 状态：已接受
- 日期：2026-08-02

## 背景

Desktop 的“系统设置 → 缓存”同时展示页面运行时数据、浏览器持久缓存、CacheStorage、本地资源库预览，以及 `.mo-gallery` 中的数据库、备份和回收站。这里混合了可再生缓存和不可再生用户数据，导致总占用口径不准确、清理范围难以理解，也不利于用清理缓存恢复页面异常。

## 决策

采用“空间管理与故障恢复”作为缓存页的首要目标。

1. 缓存页只管理可再生内容，不把资源库数据库、清单、备份、回收站和任务状态称为缓存。
2. 页面改为单页总览，不再使用缓存页内部的 master-detail 分类侧栏。
3. 页面包含两类缓存：
   - 应用数据缓存：页面运行时状态、持久化页面数据、按当前服务端与账号命名空间隔离的 CacheStorage。
   - 本地预览缓存：按需生成的 2048px 屏幕预览。
4. 顶部“可释放空间”只统计可释放的磁盘占用：持久化应用缓存、CacheStorage、本地大图预览。运行时内存只显示状态和估算量，不计入磁盘可释放空间。
5. “清理并重建”只清理应用数据缓存；本地大图预览保持独立操作。
6. 风险分级：单个小型页面缓存和 CacheStorage 可直接清理；“清理并重建”与本地大图预览清理必须二次确认。
7. 清理不删除账户、设置、照片原文件、资源库索引或组织数据。清理后相关内容在下次访问时自动重新加载或生成。
8. `.mo-gallery` 总占用、资源库数据、缩略图和预览明细移动到“系统设置 → 本地资源库 → 存储占用”，并提供“管理缓存”入口返回缓存页。
9. 系统 WebView 管理且无法准确统计或单独删除的 HTTP 图片缓存不在缓存页展示。
10. 本轮只重构现有能力，不新增缓存上限、自动清理策略或历史记录。

## 后果

- “可释放空间”不再混入不可清理的资源库数据或仅存在于内存中的页面状态。
- 用户可以从一个页面完成空间释放和页面异常恢复，同时清楚看到重建代价。
- 本地资源库的真实磁盘占用仍可查看，但其不可再生数据不会出现在清理语境中。
- CacheStorage 的统计仍是前端尽力而为；不支持时必须显示不可用状态，不能伪装为零占用。
